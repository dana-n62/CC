### **Question 2:** What Makes This Hard?

## 📚 **THE THREE PILLARS OF THIS PROJECT**

### **Pillar 1: OPERATIONS (Mechanics)**
Understanding what each operation does physically to the stacks.
```
Stack A: [3][2][1]

After 'sa' (swap):
Stack A: [2][3][1]  ← Top two swapped

After 'ra' (rotate):
Stack A: [3][1][2]  ← Top moved to bottom

After 'rra' (reverse rotate):
Stack A: [2][3][1]  ← Bottom moved to top
```

### **Pillar 2: ALGORITHM (Strategy)**
Deciding **which** operations to perform and **when**.
```
The challenge: Different input sizes need different strategies!

3 numbers   → Hardcoded (max 2-3 moves)
5 numbers   → Simple strategy
100 numbers → Need smart algorithm (< 700 moves)
500 numbers → Need optimized algorithm (< 5500 moves)
```

### **Pillar 3: IMPLEMENTATION (Code)**
Writing clean, efficient, leak-free C code.
